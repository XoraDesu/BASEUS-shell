# Contributing to BASEUS

Thank you for your interest in contributing to BASEUS.

---

## Project Identity

BASEUS has a deliberate design language and product identity. Contributions are welcome, but contribution does not automatically redefine project direction.

The project has a single owner/maintainer. The established design language is protected as product identity.

---

## How to Contribute

### Reporting Issues

- Use GitHub Issues.
- Describe the problem clearly.
- Include environment details (distribution, Hyprland version, Quickshell version).
- Include steps to reproduce when applicable.

### Submitting Pull Requests

- Fork the repository and create a branch.
- Keep changes focused and coherent.
- Follow existing code conventions.
- Ensure your changes do not break existing behavior.
- Describe what your change does and why.

### Design Proposals

Significant UI changes require a Design Proposal before implementation.

A Design Proposal should describe:

- problem;
- current behavior;
- proposed behavior;
- affected surfaces;
- design rationale;
- interaction impact;
- performance impact;
- accessibility impact.

Major identity changes require:

1. proposal;
2. impact discussion;
3. owner approval;
4. `DECISIONS.md` update.

---

## Source of Truth

Before contributing, familiarize yourself with:

- `MASTER.md` — product definition;
- `DESIGN.md` — visual and interaction design;
- `ANTI-SLOP.md` — design quality system;
- `DECISIONS.md` — accepted decisions.

Contributions should remain compatible with these documents.
